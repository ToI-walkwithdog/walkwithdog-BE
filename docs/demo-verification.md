# 개발 DB API 시연 검증 기록

검증일: 2026-09-17. 대상: localhost:5432 / toi_db (PostgreSQL).
API는 127.0.0.1:8001에서만 실행했으며 외부 배포·공개는 하지 않았습니다.
자동 테스트: 기존 29개와 신규 26개, 총 55개 통과.

## DB 적용과 보존

- 백업: `.demo-backups/toi-before-demo-g84f9e8g.dump` (Git 제외, 접근 권한 제한)
- pg_dump 성공, 비어 있지 않은 custom-format 파일과 pg_restore --list 성공 확인
- survey_id INTEGER/nullable/외래키, analysis_snapshot JSON/nullable,
  uq_matching_survey_dog 유일성 인덱스 추가 및 구조 검증 완료
- 준비 도구 --apply 재실행: 이미 적용된 상태로 추가 변경/백업 없음
- 백업의 원래 컬럼 데이터를 메모리에서 현재 행과 비교해 다음 기존 내용이 동일함을 확인:
  사용자 2명, 보호소 8곳, 강아지 20마리, 설문 1개, 매칭 결과 5개
- 기존 결과의 survey_id를 추측하여 채우거나 기존 이력을 삭제하지 않음

## 시연 데이터와 API

- 가상 사용자 ID 3, 보호소 ID 9, 강아지 ID 21~26 추가
- 시연 데이터 준비 두 번째 실행에서 생성 예정 수 모두 0, 같은 ID 반환
- 실제 API 시연으로 설문 ID 2와 3, 각 매칭 5개 생성
- 첫 설문 동시 요청 2개: 모두 HTTP 200, 동일한 결과 반환
- 같은 설문 재호출: 결과 ID/분석 유지, 중복 이력 없음
- 새 설문 매칭 후 이전 분석의 점수·이유·주의점·관리 포인트·점수 구성 보존
- 전체 이력 수를 가정하지 않고 실행에서 받은 ID로 확인
- Enum/MBTI/음수 산책 시간 오류: 각각 HTTP 422
- 없는 설문/강아지/사용자 설문: HTTP 404
- Swagger /docs: HTTP 200

가상 데이터와 검증에서 생성한 설문/이력은 DB에 남겼습니다. 각 재실행에서도 새
설문 2개가 생깁니다. 동시 요청 중 롤백으로 ID 시퀀스에 빈 번호가 생길 수 있으며
이는 중복 이력이나 유실을 뜻하지 않습니다. 실제 강아지들도 추천 후보에 포함했습니다.

백업으로 현재 DB를 덮어쓰는 복원이나 전체 백업 복원 테스트는 하지 않았습니다.
UI·인증·외부 배포 검증도 이번 범위에 포함하지 않았습니다.
