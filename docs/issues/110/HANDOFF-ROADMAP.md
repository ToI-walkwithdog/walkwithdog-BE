## 5. 브랜치, Worktree, 변경 경로와 충돌 방지

| 영역 | 주 담당 | 경로 | 규칙 |
| --- | --- | --- | --- |
| 배포 설정 | 사용자 | `deploy/`, `docker-compose.yml`, `Dockerfile`, `scripts/deploy*.sh`, `scripts/rollback.sh`, `scripts/verify_*.sh`, `docs/deployment/` | 팀원은 필요한 환경변수 목록을 Issue 댓글로 전달한다. |
| 인증, SMS | 사용자 | `app/phone_verification_service.py`, `app/sms_provider.py`, `app/auth.py`, 관련 라우터 | 팀원은 변경하지 않는다. |
| 마이그레이션 | BE 팀원 | `scripts/apply_migrations.py`(신규), `docs/migrations/README.md` | 새 SQL 번호는 `check_migrations.py --propose`로 확인하고 Issue에 파일명을 남긴다. `migrations/manifest.json`은 새 SQL을 추가하는 PR만 수정한다. |
| 보호 경로 | 공통 | `scripts/check_migrations.py`, `docs/dev-automation/` 등 | 기능 PR에서 변경하지 않고 유지보수 PR로 분리한다. |
| DB 테스트 | 공통 | `tests/*_postgres.py`, `tests/test_signup_postgres.py`, `tests/test_onboarding_integration_postgres.py`의 마이그레이션 체인 | 체인 목록은 새 SQL을 추가한 PR만 수정한다. 격리 스키마를 쓰고 공용 스키마를 만들지 않는다. |
| 초기 데이터 | BE 팀원 | `scripts/seed_dev_data.py`(신규), `scripts/sync_regions.py`(재사용) | 기존 `seed_demo.py`는 바꾸지 않는다. |
| 정책 설정 | BE 팀원 | `policies/`, `app/location_geocoder.py` | 코드 변경은 테스트와 함께 한다. |
| 공통 문서 | 공통 | `docs/TODO.md`, `docs/handoff/LATEST.md`, `docs/issues/<번호>/` | 자기 절만 추가하고, 병합 전 최신 dev를 반영해 충돌을 해소한다. |
| 기준 목록 | 공통 | `docs/dev-automation/test-baseline.json` | 충돌 시 최신 dev 반영 후 `dev_gate inventory`로 다시 만든다. 수동 병합하지 않는다. |

- 기본은 각자 메인 저장소에서 한 번에 한 Issue(`main` 모드)다. 병렬이 필요하면 `worktree` 모드를 별도 승인받아 `projects/walkwithdog-BE-worktrees/<기능명>`에 만든다.
- 사용자가 로컬에서 쓰는 `deployment-pipeline` Worktree(브랜치 `chore/deployment-pipeline`)는 사용자 PC에만 있으며 배포 작업용이다. 팀원은 같은 이름의 브랜치를 만들거나 바꾸지 않는다.
- 같은 파일을 바꾸는 PR은 한 건씩 병합한다. 먼저 병합된 변경을 후속 브랜치에 반영하고, 충돌, 마이그레이션, 기준 목록, 회귀 테스트, 독립 리뷰, CI를 다시 확인한다.

## 8. 20단계 개선 항목

비차단 성능 최적화와 코드 정리만 20단계에서 한다. 근거는 [docs/TODO.md](../../TODO.md)에 있다.
- 통계 집계와 이력 count 인덱스, 실행 계획, 커서 페이지네이션 검토
- `FINISHED_WALK_STATUSES` 중복 정리
- `app/account_status.py` 잠금 설명 문구 정리
- NOWAIT 잠금(보호소 코드, 예약)과 같은 사용자의 Step 1, 프로필, 선호 PATCH 경합 시 재시도 안내
- 오류 응답 형식(`{code, data, message}`와 `{detail}`) 통일 검토
